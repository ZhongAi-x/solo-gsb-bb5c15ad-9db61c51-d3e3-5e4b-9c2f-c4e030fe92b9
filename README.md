# 事件时序约束校验器（Temporal Constraint Checker）

用于**采访证词核对**与**事故复盘时间线分析**的 Web 应用。用户录入两类信息：

- **相对时序约束**（自然语言形式）：事件 A 比事件 B **早 / 晚** `x` 到 `y` 分钟；
- **绝对时间观测**：为任意事件录入「发生于 `start ~ end`」的观测区间，可录入多条、
  可落在不同事件上；`start = end` 即**精确时刻**（零宽区间）。

系统把**全部观测与全部相对约束接入同一张差分约束图**（Difference Constraint System），
引入虚拟「时间原点」t₀（= 最早观测起点）统一计算，实时完成：

1. **可满足性实时判定** —— 观测之间、观测与约束之间、约束之间一旦矛盾（图中出现负环）立即报警，
   三类矛盾在**同一次求解**中检出，不按锚点逐个独立判断；
2. **矛盾链高亮复核** —— 突出显示一条具体的矛盾链（可能同时包含观测边与相对约束边）：
   图上红色节点/边（含中心时间原点）、观测列表与约束列表红色行，并逐条列出环上的差分不等式，
   求和得到 `0 ≤ 负数` 的代数证据，分别映射回原始观测记录与证词；
3. **最小修复建议** —— 检测到矛盾时，以每次发现的负环为分支依据搜索
   **停用相对约束数量最少**的可满足方案（观测是事实记录，不参与停用）；并列最优方案最多展示
   5 个并按约束录入顺序稳定排序，每个方案列出需停用的约束与修复后的绝对时间窗，支持
   **不写入 localStorage 的一键预览**与**确认应用**（确认后批量停用）。搜索累计超过 2000 个
   状态即停止并标记可能不完备；若矛盾无法仅靠停用约束消除（矛盾链只缺在观测上），
   明确提示需要核对观测记录；
4. **绝对时间窗计算** —— 可满足时以时间原点为源，给出每个事件的**最早 / 最晚绝对时间**与
   相对基准的偏移；基准与换算关系直接标注在表格标题；
5. **边界依据追溯** —— 点击时间窗表中任一事件的**最早 / 最晚时间**，展示从时间原点推导该边界的
   **紧约束链**：按推导顺序逐步列出所依据的原始观测/约束、采用的上/下界侧不等式与累计偏移，
   并在**差分图、观测列表与约束列表中同步紫色高亮**；最早边界由反向图路径正确还原为原始
   观测/约束（步骤标注「反向」）。被一条精确观测直接钉住的事件给出**零步证明**；
   单边无界或无法定时的单元格不可点击，悬停可见原因。任何编辑或进入/退出修复预览都会
   自动清除旧追溯，预览中的追溯按有效约束重新计算；
6. **无法定时标记** —— 与时间原点（即任何观测）在图上没有有向通路的事件标记为「无法定时」：
   它们属于未被任何观测连通的分量，即使相对约束自洽也没有绝对时间；
7. **分层最小偏差排程** —— 系统可满足且至少存在一条观测时，可为一个或多个事件填写
   **期望时刻**，并为每个期望选择**高 / 中 / 低**优先级（默认「中」）。系统对**整体差分系统**
   按 **高 → 中 → 低 字典序**最小化各层最大偏差：先求高层的最小非负整数容差 `D_高`，
   把 `±D_高` 的钉住约束固定进差分系统后再求下一层（**不是**加权和，也不是分层各自
   排程后拼接，同样**不是**把各事件独立夹到现有时间窗），最终输出一份**同时满足全部
   启用约束、全部观测与各层容差的确定性可行排程**：每个已定时事件的实际绝对时刻、所属层级
   与相对期望的偏差，以及每层的最优 `D` 与达到 ±D 的事件；仍未与任何观测连通的事件明确标为
   「未定时」（其上的期望与层级不参与搜索）。编辑约束、观测、期望或层级后实时重算，
   矛盾状态下不显示任何旧排程结果；
8. **观测实时增删改 + 本地持久化** —— 观测的新增、编辑、删除与其他任何编辑一样实时重算并
   自动保存在浏览器 `localStorage`（修复预览除外）；
9. **旧存档自动迁移** —— 旧版本的单一「锚点事件 + 锚点绝对时间」数据在打开时自动迁移为
   锚点事件上的一条**精确（零宽）观测**，旧期望时刻与优先级字段继续兼容；
10. **示例数据** —— 内置「事故复盘（可满足）」与「采访证词冲突」两套示例；
11. **批量证词导入** —— 在「批量证词导入」面板粘贴多行 DSL（每行一条，空行与以 `#` 开头的
    整行注释被忽略），支持三类语句：

    ```text
    EVENT "名称" | "备注"
    REL "A" earlier|later "B" min..max
    OBS "事件" start..end
    ```

    名称与备注均为 **JSON 字符串**（完整转义，如 `\n`、`中`、`"\""`）；`min/max` 为非负整数且
    `min ≤ max`；时间格式为 `yyyy-MM-ddTHH:mm`（日期与时间之间也允许空格），`end < start` 视为非法。
    粘贴后**先完整解析为只读预览**：逐行列出将新增的事件、约束与观测，并标注每个引用指向
    **现有事件**还是**同批 EVENT 声明**（引用顺序无关，可前向引用）。重名或重复声明、
    引用不唯一（含现有事件重名）/ 引用不存在、REL 自引用、非法区间与非法时间格式都会
    **定位到原始行号**；**任一错误都禁止写入**。确认无误后**一次性追加合并并持久化**：
    新事件/约束/观测生成新 id 追加进现有列表，**不覆盖任何现有数据**。

技术栈：React 18 + TypeScript + Vite，纯前端、无后端依赖。

## 一条命令启动

需要已安装 Docker（含 Compose 插件）。在项目根目录执行：

```bash
docker compose up --build -d
```

启动后访问：

> **http://localhost:8080**

镜像构建时会自动完成依赖安装（`npm ci`）与生产构建（`tsc + vite build`），
容器启动即由 nginx 直接托管静态产物，**无需任何额外初始化步骤**。

常用命令：

```bash
docker compose logs -f        # 查看日志
docker compose down           # 停止并移除容器
docker compose up --build -d  # 代码更新后重新构建启动
```

### 修改访问端口

编辑 `docker-compose.yml` 的端口映射，例如改用 9090：

```yaml
ports:
  - "9090:80"
```

然后重新 `docker compose up -d`。

## 配置项

本应用无数据库、无第三方服务、无必需环境变量。可选配置：

| 配置位置 | 说明 | 默认值 |
| --- | --- | --- |
| `docker-compose.yml` 中 `ports` 左侧 | 宿主机访问端口 | `8080` |
| `vite.config.ts` 中 `server.port` | 本地开发端口 | `5173` |
| 浏览器 `localStorage` 键 `temporal-constraint-checker:v1` | 自动持久化的事件/约束/观测/期望时刻与优先级层级 | 首次打开载入可满足示例 |

数据只存于当前浏览器，点击页面右上角「清空全部数据」可清除。
旧版本存档打开时自动兼容：

- 旧版 `anchorId + anchorTime`（无 `observations` 字段）→ 迁移为锚点事件上的一条精确观测；
- 引用已删除事件、时间无效、终点早于起点的观测在迁移时被清洗/归一；
- 无优先级层级字段时，期望按「中」优先级参与排程。

存储键保持不变（`…:v1`），迁移发生在读取阶段并随即回写，刷新后即为新结构。

## 使用指南

1. **添加事件**：在「事件」面板录入关键时点（如：告警触发、服务恢复）；
2. **录入相对约束**：在「时序约束」面板选择 `事件 A —（早于/晚于）— 事件 B`，
   填写分钟区间 `x ~ y`（要求 `0 ≤ x ≤ y`；`x = y` 表示精确间隔）；
3. **录入绝对时间观测**：在「绝对时间观测」面板选择事件并填写
   `发生于 [最早时刻] ~ [最晚时刻]`：两个时刻相同即**精确时刻**（零宽区间）。
   可为同一事件或不同事件录入多条观测；至少一条观测后才能计算绝对时间窗；
4. **查看实时结论**：
   - 顶部绿色横幅：观测与约束可满足，底部表格给出每个事件的绝对时间窗
     （基准 t₀ = 最早观测起点，标题中直接给出换算关系）；
   - 红色横幅：存在矛盾，红色矛盾链给出可逐步复核的不等式链，链上的
     **绝对时间观测与原始证词分组列出**；其下方「最小修复建议」给出停用相对约束最少的方案；
     若矛盾无法靠停用约束消除，会明确提示核对观测记录；
   - 「无法定时」：该事件与任何观测之间都没有约束通路，请补充观测或连接二者的约束；
5. **追溯边界依据**：在时间窗表中点击任一事件的**最早时间**或**最晚时间**，
   表下方展开该边界的推导链——从时间原点 t₀ 出发逐步列出用到的原始观测/约束（含录入序号）、
   采用的上界/下界侧不等式与累计偏移，差分图、观测列表与约束列表同步紫色高亮；
   再次点击同一单元格或点击「关闭」收起。精确观测事件显示零步证明；
   单边无界 / 无法定时的单元格不可点击，悬停可查看原因。编辑数据或进入/退出修复预览会
   自动清除当前追溯；
6. **核对矛盾**：可逐条**取消勾选**可疑证词（相对约束），观察矛盾链是否消失，
   快速定位冲突来源；观测作为事实记录不提供停用开关，需要时直接编辑观测时刻；
7. **分层最小偏差排程**：系统可满足且存在观测时，底部排程面板可为任意事件填写
   **期望时刻**（留空则不参与），并选择**高 / 中 / 低优先级**（默认「中」）。
   系统按 **高 → 中 → 低 字典序**实时求解：先求高层最小容差 `D_高` 并固定，再依次求中、低层，
   最终给出一份同时满足全部启用约束、全部观测与各层容差的确定性可行排程。面板**按层**展示
   每层最优 `D`、参与事件数、本层最大偏差与**达到 ±D 的事件**；结果表逐事件列出**层级**、
   实际绝对时刻、相对基准偏移、期望时刻与期望偏差；未与任何观测连通的事件在结果中明确标为
   「未定时」，其上填写的期望与层级不参与搜索并注明未生效。
   编辑约束、观测、期望或层级后排程实时重算；矛盾时面板不展示任何旧结果；
8. **采纳修复建议**：
   - 点击方案卡片上的**一键预览**：相关相对约束被临时停用（置灰并标记“预览停用”），
     图与时间窗立即按修复后的状态展示（观测保持生效）；预览**只存在于内存，不写入 localStorage**，
     可随时「退出预览」返回原数据，任何编辑操作也会自动退出预览；
   - 点击**确认应用**：方案中的约束被**批量停用**并持久化；
   - 并列最优方案超过 5 个时只展示按约束录入顺序最靠前的 5 个（会注明总数）；
     搜索累计达到 2000 个状态仍未结束时，面板会提示**结果可能不完备**。
9. **批量证词导入**：在「绝对时间观测」下方的「批量证词导入」面板粘贴多行 DSL
   （可展开面板顶部的「DSL 语法说明与示例」复制模板）：
   - `EVENT "名称" | "备注"`：声明新事件，名称/备注为 JSON 字符串；
   - `REL "A" earlier|later "B" min..max`：A 比 B 早/晚 min~max 分钟（非负整数）；
   - `OBS "事件" start..end`：绝对时间观测区间（两端相同即精确时刻）；
   - 粘贴后实时给出**只读预览**：逐行列出将新增的内容，并在引用名后用徽标标明
     「现有事件 / 本批新增」；所有错误（重名、重复声明、引用不唯一/不存在、非法区间、
     非法时间格式、JSON 转义错误等）按**原始行号**列出，**有错误时「确认导入」按钮禁用**；
   - 点击**确认导入**：一次性追加合并并自动保存，现有事件/约束/观测不受影响、不被覆盖。

### 状态图例（时间窗表）

| 状态 | 含义 |
| --- | --- |
| **可定时** | 最早与最晚绝对时间都能由观测与约束推出（直接被观测钉住的事件带「直接观测」标记） |
| **仅单边有界** | 只能推出最早或最晚一侧（另一侧无界） |
| **无法定时** | 与任何绝对时间观测都无有向通路，属于未被观测连通的分量 |

## 算法说明

**统一建模。** 设 n 个事件的时间变量为 t₀…tₙ₋₁，另引入一个虚拟**时间原点**变量 `t0`
（节点下标 n），其真实时刻取全部有效观测起点的最小值 `baseISO`。

每条相对约束 `A 比 B 早 x~y 分钟`（即 `x ≤ t_B − t_A ≤ y`）转换为两条
**差分不等式**，在图中对应两条带权有向边（边 `u → v` 权 `w` 表示 `t_v − t_u ≤ w`）：

- 上界：`t_B − t_A ≤ y` ⇒ `A → B, 权 y`
- 下界：`t_A − t_B ≤ −x` ⇒ `B → A, 权 −x`

`A 比 B 晚 x~y` 时方向互换。

每条绝对时间观测 `事件 e 发生于 [start, end]`，令 `lo/hi` 为相对 `baseISO` 的分钟偏移，
则 `lo ≤ t_e − t0 ≤ hi` 转换为：

- 上界：`t_e − t0 ≤ hi` ⇒ `t0 → e, 权 hi`
- 下界：`t0 − t_e ≤ −lo` ⇒ `e → t0, 权 −lo`

精确时刻观测即 `lo = hi` 的零宽区间（两条边把 t_e 双向钉死在 t0 + lo）。

**观测边与约束边是同一张图的边**，因此：

- **可满足性**：整个系统可满足 ⇔ 图中不存在负权环。使用带「超级源点」（全部节点初始
  距离为 0）的 Bellman-Ford 在第 (n+1) 轮检测松弛，O(V·E)。观测间、观测与约束间、
  约束间的三类矛盾在这一次求解中同时被检出——不存在「先定锚点、再逐锚点判断」的步骤；
- **矛盾环提取**：从第 n+1 轮仍被松弛的边沿前驱指针回溯，先走入环内再裁掉环外尾巴，
  得到权重之和严格小于 0 的环；环经过时间原点即说明矛盾涉及绝对时间观测。展示时按边的
  来源分别映射回观测记录与自然语言证词；
- **绝对时间窗**：以 t0 为源跑最短路得到各事件「最晚偏移」`t_i − t0` 的最小上界，
  在反向图上跑最短路得到「最早偏移」，加上 baseISO 即绝对时间。正/反向均不可达说明
  该事件所在分量没有任何观测与之相连，即「无法定时」；
- **边界依据追溯**：可满足时，最短路的前驱边即从 t0 出发的紧约束链。
  最晚边界直接沿正向图前驱边回溯；最早边界在反向图上取前驱边后，
  逐步还原为原始观测/约束边（行走方向与原始边相反，权重与上/下界侧不变），
  累计偏移为路径权重前缀和（最早边界取负）。链上唯一一条边就是精确观测本身时退化为
  零步证明；
- **最小修复建议**：在「停用哪些相对约束可使系统恢复可满足」中求**停用数最少**的方案
  （最小击中集）。采用以负环为分支依据的逐层 BFS（branch and bound）：
  1. 对当前停用集合跑一次 Bellman-Ford；
  2. 若已无负环，当前集合即为可行方案；
  3. 否则任取一条负环 C——任何可行方案都必须再停用 C 上的至少一条**相对约束**
     （观测边不可停用，不产生分支），故只需对 C 上的不同约束逐一分支，完备且不会枚举
     无关约束；
  4. 按停用数 0,1,2,… 逐层展开，**第一次出现可行方案的层即给出最少停用数**，
     同层全部状态都会被考察，以收集并列最优方案；候选项按约束录入顺序展开，
     同层方案按停用约束的录入顺序字典序稳定排序，最多展示 5 个。

  搜索用全局 visited 集合（停用集合的规范化下标元组）去重；累计访问状态数达到
  **2000** 上限即停止：若已找到方案，最少停用数仍已被证明（但并列方案列表可能不全）；
  若尚未找到方案，则明确标记结果可能不完备。当搜索穷尽且剩余负环上没有可停用的约束时，
  报告 observationConflict——矛盾只能通过核对观测记录解决。每个候选方案复用 `analyze`
  计算修复后时间窗（观测保持生效）；
- **分层最小偏差排程**：设期望事件 `i` 相对时间原点的期望偏移为 `d_i`（由期望时刻与
  baseISO 相减得到，分钟取整），其优先级层级为 `L(i)`（高/中/低，缺省为中）。按
  **高 → 中 → 低**字典序逐层优化，对每一层：
  1. **上界**：累计差分系统（原始约束 + 全部观测 + 所有更高层已固定的钉住约束）的任一
     可行势 `t*`（超级源点 Bellman-Ford）给出可行上界
     `D_ub = max_{i 属于本层} |(t*_i − t*_t0) − d_i|`；
  2. **二分**：在 `[0, D_ub]` 上二分最小的可行非负整数 `D_L`。对候选 `D`，把本层每个
     期望事件「钉」到时间原点上：加边 `t0 → i, 权 d_i + D` 与 `i → t0, 权 D − d_i`，即
     `d_i − D ≤ t_i − t0 ≤ d_i + D`；在该**整体**差分图上做负环检测判定可行性；
  3. **固定容差**：把本层 `±D_L` 的钉住边**永久并入累计边集**，再求下一层——低层优化
     始终受高层钉住约束限制，绝不可能牺牲高层已达成的容差；尚未求到的更低层此时
     不参与钉住（保持自由），符合字典序语义。

  全部层级求完后，取累计钉住图上的一组可行势（平移到 t0 = 0）作为**唯一输出排程**：
  它同时满足全部启用约束、全部观测与各层最优容差；边集与边顺序确定时 Bellman-Ford
  结果确定，故输出是确定性的。由于每层 `D_L` 最小（`D_L − 1` 在约束更少的系统上已不可行），
  最终排程中每层必然有事件达到 ±D_L。

  本算法**不使用加权和、也不分层各自排程后拼接**：所有可行性判定与最终输出都产生自
  同一个累计差分图。也不能用「各事件独立夹到现有时间窗」代替整体搜索：事件间存在耦合，
  例如约束 `t_Y = t_X + 5` 时，窗口为 `X∈[0,5]`、`Y∈[5,10]`；若期望 `X=+10`、`Y=0`，
  独立夹窗会把 `X` 夹到 5、`Y` 夹到 5（各偏差 5）而误判 `D=5`，
  但 `t_X=5 ⇒ t_Y=10`（偏差 10）——整体搜索给出的正确答案是 `D=8`。
  字典序的效果：若 `t_Y = t_X`、期望 `X=+10`（高）、`Y=0`（低），同层平级时最小最大偏差
  为 `D=5`（`t_X=t_Y=5`）；分层求解则高层先把 `X` 钉到 10（`D_高=0`），低层 `Y` 被迫取 10
  （`D_低=10`）——高层目标严格优先。与时间原点不连通的事件不参与搜索，在结果中标记为
  「未定时」。
- **旧存档迁移**：旧状态只有 `anchorId/anchorTime` 时，读取阶段直接构造
  `{eventId: anchorId, start: anchorTime, end: anchorTime}` 的零宽观测插入 `observations`，
  此后所有计算路径与手工录入的精确观测完全一致（同一张图、同一组边），无需为迁移数据
  保留任何特殊分支。
